SftpSync Auto-Queue Worker

Implementation plan for real SFTP sync: DB-driven job scheduling, incremental scan/enqueue, and serial download worker. Branch: feat/auto-queue-job.

Goal: Replace DevelopmentSimulationService with a real background sync engine that polls enabled jobs from PostgreSQL, scans SFTP for new/changed files, enqueues work into download_queue_items (hybrid grouping model), and downloads to the local filesystem — broadcasting run/queue updates via existing SignalR infrastructure.

References: docs/grouping-rules.md, folder grouping plan, ISftpDirectoryScanner in SftpSync.Business/Scanning/.

Status: Requirements locked — ready to implement

  • SignalR broadcaster (RunUpdated, QueueItemUpdated) is ready for real worker events.

Architecture

JobSchedulerHostedService (every 10s)
  → query due enabled jobs
  → skip if active run exists for job
  → update last_polled_at
  → create run (queued → scanning)
  → scan SFTP (RealSftpDirectoryScanner)
  → diff new/changed vs synced state
  → upsert queue items
  → if no work: run → completed
  → else: run → downloading

DownloadWorkerHostedService (global serial)
  → claim next queued item (any job/run)
  → if is_group: download all internal leaves recursively
  → else: download single file to local path
  → update item + run aggregates + SignalR
  → when run has no pending items: run → completed

Two-phase model

  1. Scan phase — job checks what exists on SFTP; matching work is written to the queue.
  2. Download phase — separate worker pulls from the queue and transfers files to disk.

Scans for different jobs may run in parallel. Downloads are strictly serial (one at a time globally).

Implementation Phases

Phase 1 — Database & Repository Writes

Problem: Repositories are read-only today. Runs and queue items are only written by dev simulation raw SQL.

1a. SQL functions / migration

New timestamped migration under SftpSync.Infrastructure/Migrations/Schema/ (e.g. 20260530xxxx_AddWorkerRepositoryFunctions):

Function Purpose
core.get_due_sftp_sync_jobs() Enabled jobs where now() >= last_polled_at + polling_interval (or last_polled_at IS NULL)
core.mark_sftp_sync_job_polled(p_id) Set last_polled_at = now()
core.job_has_active_run(p_job_id) True if run status IN (queued, scanning, downloading)
core.create_sftp_sync_run(p_job_id) INSERT run with status queued, return row
core.update_sftp_sync_run_status(...) Status transitions + counters + error_message
core.upsert_download_queue_item(...) INSERT or UPDATE on (job_id, remote_path) conflict — reset status to queued when re-enqueueing
core.get_synced_remote_state(p_job_id) Returns remote_path, remote_modified_at, file_size_bytes, status for change detection
core.claim_next_download_queue_item() FOR UPDATE SKIP LOCKED — pick oldest queued item globally

Phase 3 — Change Detection (Incremental Sync)

For each scanned entry (visible + internal leaves):

existing = synced state for (job_id, remote_path)

if existing is null:
    → NEW → enqueue (status = queued)

else if existing.status == 'completed'
     AND existing.remote_modified_at == scanned.mtime
     AND existing.file_size_bytes == scanned.size:
    → UNCHANGED → skip

else:
    → CHANGED → re-enqueue (reset status, bytes_downloaded = 0, assign new sync_run_id)

Failed items (requirement 3C): During scan, query items with status = 'failed' for this job → reset to queued, attach to current run.

Groups: Compare group row aggregates (total bytes + max mtime). If any leaf in subtree changed, re-enqueue the group row and all internal leaves.

Run initialization

  • total_file_count = count of visible entries actually enqueued (not skipped)
  • total_bytes = sum of enqueued visible entry bytes
  • If both are 0 → run → completed immediately (empty scan audit trail)
Milestone: Incremental enqueue works — unchanged files are skipped, new/changed/failed are queued.

Phase 4 — Job Scheduler

JobSchedulerHostedService (every 10 seconds):
  dueJobs = GetDueJobsAsync()
  for each job in dueJobs (parallel Task.WhenAll ok):
    if HasActiveRunAsync(job.Id): continue
    MarkPolledAsync(job.Id)
    run = CreateRunAsync(job.Id)
    broadcast RunUpdated (queued)
    await orchestrator.ScanAsync(job, run)

Manual run — POST /api/sftp-sync-jobs/{id}/run

  • Runs immediately even if not due yet
  • 409 Conflict if job already has active run
  • 400 Bad Request if job disabled
  • 404 if job not found
  • Do not update last_polled_at on manual run (so scheduled poll is not delayed)
Milestone: Enabled jobs auto-poll from DB on interval.

Phase 5 — Scan Orchestration

SyncRunOrchestrator.ScanAsync:

  1. Transition run → scanning (broadcast)
  2. Open SFTP connection from job's connection_profile_id
  3. Call RealSftpDirectoryScanner.ScanFirstLevelAsync
  4. Run ChangeDetector on visible + internal entries
  5. Upsert changed/new items with sync_run_id = run.Id
  6. Re-queue failed items for this job
  7. Recalculate run totals
  8. If no items enqueued → run → completed (broadcast)
  9. Else → run → downloading (broadcast)

Scan errors (connection failure, auth, etc.): run → failed with error_message; no retry until next poll.

Phase 6 — Download Worker

DownloadWorkerHostedService (global serial loop):
  item = ClaimNextDownloadQueueItem()
  if item is null: delay 1s; continue

  if item.is_group:
    leaves = GetLeavesForGroupAsync(runId, groupRemotePath)
    download each leaf to local destination_path
    update group aggregates as leaves progress
  else:
    download single file via SFTP Get → local path

  on success: item → completed
  on failure: item → failed (error_message); do NOT fail entire run

  update run aggregates (bytes, counts, rate)
  broadcast QueueItemUpdated + RunUpdated

  if run has no items in (queued, comparing, downloading):
    run → completed (failed_file_count may be > 0)

Local filesystem writes

  • Create parent directories as needed
  • Write to temp file → atomic rename on success
  • Map destination_path from queue item directly to local path
  • Preserve relative structure under job's destination_path for group subtrees

Group download flow

  1. Claim group row (is_group = true)
  2. Load internal leaves via GetLeavesForGroupAsync
  3. Download each leaf sequentially (global serial already enforced)
  4. Update group row bytes_downloaded as leaves complete
  5. Group → completed when all leaves terminal; individual leaf failures do not fail the group row
Milestone: Files land on local disk; dashboard shows real progress.

Risks & Mitigations

Risk Mitigation
Long downloads block other jobs (serial) Acceptable for v1; config hook for future N
(job_id, remote_path) uniqueness across runs Upsert pattern; re-enqueue updates same row
SFTP connection reliability Per-operation connect/disconnect; run-level failure on scan errors
Large group subtrees Scanner discovers all leaves at scan time (existing design)
Removing dev sim breaks local demo without SFTP Document test connection profile setup in README
